## 코드 수정에 관하여

1. 무엇이 위험했는지?
- API_KEY 와 DB_URL과 같은 비밀값이 기존 legacy_report.py에 작성되어 있었다. 이러한 비밀 정보가 git 저장소에 커밋되면 다른 사람들이 저장소를 통해 API Key나 DB 접속 정보에 접근할 수 있기 때문에 보안상의 문제가 있었다. 

2. 어떻게 수정했는지?
- API key와 DB 접속 정보를 코드에서 제거하고 .env 파일에 별도로 저장했다. python-dotenv를 사용하여 환경변수로 불러올 수 있도록 코드를 작성하였다. 또한 .gitignore에 .env를 추가하여 해당 파일이 git에 올라가지 않도록 설정했다.

3. 만약 실키가 1차 커밋으로 노출되었다면 올바른 대응 절차는 무엇인지?
- 즉시 해당 키를 폐기하고 새 키를 발급받는다. 새 키는 .env에 작성하고 .gitignore을 정비한다. 사용량, 청구 내역을 점검하고 필요시 사업자에 신고한다.
